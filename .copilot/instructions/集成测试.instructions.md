# VS Code 插件集成测试约定

> 本文档记录 `inherit-profile-plus` 集成测试的环境、运行方式、沙箱机制与**常见易错点**。
> 其他模型/开发者在本项目上编写或调试集成测试时，**务必先读本文档**，避免重复踩坑。

---

## 一、测试分层

| 层级 | 位置 | 运行命令 | 特点 |
|------|------|---------|------|
| **单元测试** | `src/test/unit/**/*.test.ts` | `npm run unit-test` | 纯函数测试，无需 VS Code 宿主，快（~400ms） |
| **集成测试** | `src/test/integration/**/*.test.ts` | `npm test` | 需启动真实 VS Code 宿主，慢，涉及文件系统/配置/watcher |

**改动通用函数（`readJSON` / `mergeInheritedExtensions` / `splitRawSettingsByClosingBrace` 等）→ 必须同时跑 `npm run unit-test` 并人工检查数组路径测试。**

---

## 二、运行方式

```powershell
# 首次：安装依赖（node_modules 缺失时 tsc 会报 "不是内部或外部命令"）
npm install

# 单元测试（先 compile:test 再 mocha）
npm run unit-test

# 集成测试（启动真实 VS Code 宿主）
npm test
```

**package.json scripts：**
```json
"compile": "tsc -p ./",
"compile:test": "tsc -p ./tsconfig.test.json",
"pretest": "npm run compile:test && npm run lint",
"test": "vscode-test --config ./vscode-test.config.mjs",
"unit-test": "npm run compile:test && mocha --ui tdd \"out/test/unit/**/*.test.js\""
```

**`vscode-test.config.mjs`：**
```js
export default defineConfig({
  files: "out/test/integration/**/*.test.js",
});
```

> ⚠️ 集成测试跑的是**编译产物** `out/test/integration/**/*.test.js`，不是 `.ts` 源码。改完测试必须重新编译（`npm test` 的 `pretest` 会自动 `compile:test`）。

## 三、沙箱机制（核心）

集成测试**不碰真实用户 Profile**，而是在临时目录里造一套假的 VS Code 用户目录结构：

```
<tmp>/inherit-profile-tests-XXXX/
└── User/
    ├── globalStorage/
    │   ├── storage.json              ← 模拟 Profile 注册表（userDataProfiles）
    │   └── alexthomson.inherit-profile/   ← globalStorageUri 指向这里
    └── profiles/
        ├── child-profile/
        │   ├── settings.json
        │   └── extensions.json
        └── parent-profile/
            ├── settings.json
            └── extensions.json
```

**关键辅助函数（`extension.test.ts` 底部）：**

| 函数 | 作用 |
|------|------|
| `createContext(rootDir)` | 造一个 mock `ExtensionContext`，`globalStorageUri` 指向沙箱，`globalState` 用内存 Map |
| `writeStorage(rootDir, current, extras)` | 写 `storage.json`（含 `profileMenu` + `userDataProfiles`） |
| `writeStorageWithEmptyWindowAssociation(...)` | 写 VS Code 1.127+ 风格的 `storage.json`（`profileAssociations.emptyWindows`） |
| `writeProfileSettings(rootDir, profile, raw)` | 写某 Profile 的 `settings.json`（`profile` 为 `undefined` = Default Profile） |
| `writeProfileExtensions(rootDir, profile, exts)` | 写某 Profile 的 `extensions.json` |
| `createExtension(id, metadata?)` | 造一个扩展条目 `{ identifier: { id }, metadata? }` |
| `waitForSettings(path, predicate, timeout)` | **轮询**等待文件内容满足条件（watcher 异步触发用） |
| `updateConfig(key, value)` | 改 `inheritProfile.*` 配置（`ConfigurationTarget.Global`） |

**`setup` / `teardown` 约定：**
- `setup`：创建临时沙箱目录 + 重置配置（`parents`/`showMessages`/`inheritExtensions` 置 `undefined`）
- `teardown`：重置配置 + 删除沙箱目录
- **每个测试用例必须自己重置它改过的配置**，否则污染后续用例

## 四、⚠️ 常见易错点（其他模型最常犯）

### 1. 扩展自动激活与测试争抢全局状态

**问题**：`activate()` 在测试环境也会跑（`runOnStartup` 等），与测试用例争抢 `inheritProfile.parents` 配置和用户设置文件写入，导致 `File Modified Since` / `Overlapping edit` 竞态失败。

**解决**：`extension.ts` 的 `activate()` 开头有：
```ts
if (context.extensionMode === vscode.ExtensionMode.Test) {
  return;  // 测试环境跳过自动对账/监听
}
```
**测试用例直接调用底层函数**（`updateCurrentProfileInheritance` / `register*Watcher`），不依赖自动激活。**不要删这段守卫。**

### 2. watcher 是异步的，必须轮询等待

**问题**：`registerCurrentProfileSaveWatcher` 注册后，OS 级 watch 建立有延迟；文件写入后 watcher 触发 + 防抖 + 重新对账也是异步的。直接 `await fs.writeFile(...)` 后立即断言会失败。

**解决**：
- 注册 watcher 后先 `await new Promise(r => setTimeout(r, 500))` 让 watch 稳定
- 用 `waitForSettings(path, predicate, 15000)` 轮询等待结果，**不要用固定 sleep**
- 涉及 watcher 的用例设 `this.timeout(20000)`

### 3. 自身写入 vs 外部编辑的区分

**问题**：扩展自己写文件也会触发 watcher，若不区分会无限循环对账。

**解决**：`isManagedFileSelfWrite()` 两级判断（进程内 Map + 磁盘 `.inherit-token` 标记）。测试"不重复对账"时，断言**文件内容在等待后逐字节稳定**（而非断言"没触发"，因为触发与否不可直接观测）。

### 4. `readJSON` 校验失败返回 `undefined`，不是 `{}`

**问题**：1.8.4 事故根源——`readJSON` 校验失败返回 `{}`，下游 `collectInheritedExtensions` 无法区分"文件真空"和"校验误杀"，**静默清空扩展**。

**解决**：`readJSON` 现在对结构损坏（括号不平衡、双顶层闭合 `]},`）返回 `undefined`；`readExtensionsArray` 对非数组/损坏返回 `undefined`。**调用方必须跳过对账，绝不能当成空数组。** 写测试时若模拟损坏文件，要断言"扩展未被清空"。

### 5. `applyEdits` 重叠编辑（Overlapping edit）

**问题**：`jsonc-parser` 的 `modify` 对同一位置多次编辑会抛 `Overlapping edit`。典型场景：两个 key 都不存在时，一次 `applyEdits` 里同时插入 `_originallyOwnExtensions` 和 `optedOutExtensions`。

**解决**：**逐个 `applyEdits`**，不要合并。见 `profiles.ts` 中回写元数据的注释。

### 6. 根 Profile（无 parents）的扩展保护（issue #5）

**问题**：VS Code 降级会打乱继承元数据，导致根 Profile 扩展被当"悬空引用"清空。

**解决**：`mergeInheritedExtensions` 中 `parentProfiles.length === 0` 时，所有 inherited 扩展**退还为 own 保留**，绝不丢弃。测试用例：`"inherited extensions are preserved as own when no parents (issue #5)"`。

### 7. 测试环境无 `globalState` 时的防御

**问题**：mock context 的 `globalState` 可能缺失。

**解决**：`getParentSnapshots` / `setParentSnapshot` 等函数对 `!context.globalState` 做防御性返回。写新函数时也要考虑。

### 8. 终端输出问题（本机环境）

**问题**：本机 PowerShell 终端偶发 PSReadLine 渲染错误 / scrollback 溢出，导致命令输出丢失。

**解决**：长输出命令重定向到文件再读；或用 `mode=async` 拿终端 ID 后 `get_terminal_output` 轮询。

## 五、编写新集成测试的检查清单

- [ ] 用例在 `setup` 里已重置相关配置（或用例内 `updateConfig` 后 `teardown` 恢复）
- [ ] 用沙箱辅助函数造数据，**不碰真实 Profile**
- [ ] 涉及 watcher 的用例：注册后 sleep 500ms + `waitForSettings` 轮询 + `this.timeout(20000)`
- [ ] 涉及文件写入的用例：考虑自身写入 vs 外部编辑的区分
- [ ] 涉及损坏文件的用例：断言"未被清空"而非"被清空"
- [ ] 改完跑 `npm run unit-test`（快）+ `npm test`（集成）
- [ ] 若改了 `src/` 结构，同步更新 `.copilot/instructions/结构.instructions.md`
