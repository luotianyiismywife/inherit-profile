## extension.ts — 扩展入口点

**用途**：VS Code 扩展的激活入口。负责注册命令、启动时自动触发继承同步、监听 Profile 切换、跨设备标记恢复。

### 导出函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `activate` | `(context: vscode.ExtensionContext) => Promise<void>` | 扩展激活入口。注册 5 个命令 → 注册 `setKeysForSync` → 恢复扩展标记 → 版本检测触发全量重建 → 按配置启动各类监听器 |
| `deactivate` | `() => void` | 扩展停用入口（空实现） |

### 注册的命令

| 命令 ID | 说明 |
|---------|------|
| `inherit-profile.applyInheritanceToCurrentProfile` | 对当前 Profile 应用继承（设置 + 扩展） |
| `inherit-profile.removeInheritedSettingsFromCurrentProfile` | 移除当前 Profile 的继承内容 |
| `inherit-profile.setParentProfiles` | 交互式选择父级 Profile（排除自身及后代），写入后全量重建 |
| `inherit-profile.showInheritanceTree` | 在 OutputChannel 中展示继承树 |
| `inherit-profile.forceReconcile` | 从根 Profile 开始逐级全量重建 |

### 内部函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `checkAndRestoreMarkers` | `(context: vscode.ExtensionContext) => Promise<void>` | 启动时检查 `extensions.json` 中继承标记是否丢失，尝试从 `globalState` 备份恢复。跨设备同步后标记可能丢失，此函数负责找回 |

### 激活流程（`activate` 执行顺序）

1. 注册 5 个命令
2. 注册 `setKeysForSync`（`inheritProfile.extensionMarkers` + `inheritProfile.parentSnapshots`）
3. 调用 `checkAndRestoreMarkers` 恢复扩展标记
4. 检测扩展版本变化（`inheritProfile.lastVersion`），变化时全量重建
5. `runOnStartup` — 启动时对当前 Profile 同步
6. `runOnProfileChange` — 注册 Profile 切换监听
7. `runOnCurrentProfileSave` — 注册当前 Profile 保存监听
8. `runOnParentProfileSave` — 注册父级 Profile 保存监听

**用途**：Profile 继承的核心实现。包含设置继承（settings.json）和扩展继承（extensions.json）的完整流程，以及反向索引、级联触发、全量重建等功能。

| `collectInheritedExtensions` | `(context, currentExtensions, currentProfileName, profiles, originallyOwn?, optedOutList?, parentProfileNamesOverride?) => Promise<{extensions, originallyOwn, optedOut}>` | **7 步全量对账扩展继承**：① 读取元数据 → ② 转换旧标记 → ③ 注入 optedOut → ④ 一致性校验 → ⑤ 收集父级扩展 → ⑥ `mergeInheritedExtensions` 全量对账 → ⑦ 后处理（opt-out 误判修复 + 父级禁用过滤）→ ⑧ 统计 |

### 继承流程（`updateCurrentProfileInheritance` 完整链路）

```
触发
  │
  ├─ 级联检查（如有 triggerProfileName，检查当前 Profile 是否为后代）
  │
  └─ applyInheritedSettings()
       │
       ├─ ① 移除旧的 inherited 设置块
       ├─ ② 计算应继承的设置（父 − 子）
       ├─ ③ 写入新的 inherited 设置块
       │
       └─ ④ collectInheritedExtensions() — 7 步全量对账
            │
            ├─ ① 读取 settings.json 元数据（originallyOwn, optedOut）
            ├─ ② 转换旧标记 inheritedFromProfile → inheritProfile.inherited
            ├─ ③ 注入 optedOut 标记到 extensions.json
            ├─ ④ 一致性校验（settings.json 列表 ↔ extensions.json 标记）
            ├─ ⑤ 收集父级扩展（含禁用扩展 ID）
            ├─ ⑥ mergeInheritedExtensions() 全量对账
            ├─ ⑦ 后处理：opt-out 误判修复 + 父级禁用过滤
            └─ ⑧ 统计新增/移除
       │
       ├─ ⑤ 写回 extensions.json
       ├─ ⑥ 回写 _originallyOwnExtensions + optedOutExtensions 到 settings.json
       └─ ⑦ 备份 parentNameMap 到 globalState
```

### 全量重建流程（`reconcileAllProfiles`）

```
① 获取全量 Profile 映射
② 使反向索引缓存失效
③ 构建继承图（parent → children）
④ BFS 拓扑排序：保证父级先于子级同步
⑤ 逐级调用 syncProfileByName()
    ├─ 移除旧 inherited 设置块
    ├─ 计算并写入新继承设置
    └─ 扩展继承（同 7 步对账）
```

## profileWatchers.ts — 文件系统监听器

**用途**：监听 Profile 相关文件的变更事件并触发继承同步。包括 Profile 切换、当前 Profile 保存、父级 Profile 保存。

### 导出函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `updateInheritedSettingsOnProfileChange` | `(context: vscode.ExtensionContext) => Promise<void>` | 监听 `storage.json` 变化（Profile 切换）。去重（mtime 检测），变化后调用 `reconcileAllProfiles` 全量重建 |
| `registerCurrentProfileSaveWatcher` | `(context: vscode.ExtensionContext) => Promise<void>` | 监听当前 Profile 的 `settings.json` 保存。通过 `isManagedFileSelfWrite` 跳过自身写入。Profile 切换时自动重新订阅。防抖 250ms 后全量重建 |
| `registerParentProfileSaveWatcher` | `(context: vscode.ExtensionContext) => Promise<void>` | 监听父级 Profile 的 `settings.json` + `extensions.json` 保存。从配置读取 `inheritProfile.parents`，解析路径后创建 watcher。配置变更时自动重建 watcher 并触发对账。防抖 500ms。重复触发防护（500ms cooldown）|

### 内部函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `createFileWatcher` | `(filePath: string) => vscode.FileSystemWatcher` | 创建单文件的 VS Code watcher。使用 `RelativePattern` 确保能监听工作区外的文件（Profile 文件在 globalStorage 下） |

### 关注点

- 所有 watcher 在 Profile 切换时通过监听 `storage.json` 自动重新订阅
- `registerCurrentProfileSaveWatcher` 中 `settingsWatcher` 随 Profile 切换自动销毁重建
- `registerParentProfileSaveWatcher` 中 `parentWatchers` 在配置变更或 Profile 切换时销毁重建
- `onDidChangeConfiguration` 继承配置变化时会 `invalidateInheritanceGraph` 并触发对账

## selfWriteTracker.ts — 自写内容跟踪器

**用途**：跟踪扩展自身对文件的写入内容，用于区分"自身的写入"和"外部的编辑"。防止文件 watcher 对自身写入产生反应，避免无限循环。

### 导出类

#### `SelfWriteTracker`

| 方法 | 签名 | 说明 |
|------|------|------|
| `record` | `(filePath: string, content: string) => void` | 记录某路径的最新写入内容 |
| `isSelfWrite` | `(filePath: string, content: string) => boolean` | 检查某路径的最新内容是否匹配记录（是自身写入则返回 true） |
| `forget` | `(filePath: string) => void` | 清除某路径的记录 |

### 实现细节

- 内部使用 `Map<string, string>` 存储（路径 → 内容）映射
- 仅在 `profiles.ts` 的 `writeManagedFile` 中调用 `record`
- `isManagedFileSelfWrite` 是对 `isSelfWrite` 的一层封装导出
- 匹配策略是严格按字符串全等比较

## debounce.ts — 防抖触发器工具

**用途**：提供防抖机制，合并短时间内连续触发的异步操作，避免高频事件导致重复执行。

### 导出类型

| 类型 | 说明 |
|------|------|
| `DebouncedTrigger` | 可调用函数 + `dispose()` 方法的接口。调用它调度 action 在延迟后执行，再次调用重置计时器 |

### 导出函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `createDebouncedTrigger` | `(action: () => Promise<void> \| void, delayMs?: number) => DebouncedTrigger` | 创建防抖触发器。delayMs 默认 250ms。特点：① 调用间防抖合并 ② 执行中再次触发排队（最多 1 个排队） ③ `dispose()` 取消未执行的调度 |

### 行为说明

```
多次调用:  A   B   C
             \  |  /
              \ | /  ← 每次调用重置计时器
               \|/
             延迟后
                |
             执行 D  ← 只执行一次
```

## disabledExtensions.ts — 禁用扩展读取

**用途**：从 VS Code 的 SQLite 数据库 `state.vscdb` 中读取各 Profile 已禁用的扩展 ID 列表，用于过滤父级中已禁用的扩展不被继承。

### 导出函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `getDisabledExtensions` | `(profileDir: string) => Promise<string[]>` | 读取指定 Profile 目录下 `globalStorage/state.vscdb` 中 key 为 `extensionsIdentifiers/disabled` 的 JSON 值，解析出禁用扩展 ID 数组 |

### 内部函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `getSqlJs` | `() => Promise<any>` | 延迟初始化 `sql.js` WASM 模块，返回单例 Promise |
| `parseDisabledIds` | `(json: string) => string[]` | 解析禁用扩展的 JSON 字符串，提取 `id` 字段 |

### 注意事项

- 使用 `sql.js`（纯 JS WASM 实现 SQLite），无需 native 模块编译
- `locateFile` 路径硬编码为相对于 `__dirname` 的 `node_modules/sql.js/dist/`，使用打包工具时需注意
- 数据库读取失败或 key 不存在时静默返回空数组

## 数据流关系图

```
extension.ts (激活入口)
  │
  ├─► profiles.ts (核心逻辑)
  │     ├─► profileSettings.ts (工具函数)
  │     └─► selfWriteTracker.ts (自写跟踪)
  │
  └─► profileWatchers.ts (文件监听)
        ├─► profiles.ts
        ├─► profileSettings.ts (路径解析)
        └─► debounce.ts (防抖)

profiles.ts
  ├─► profileSettings.ts (几乎所有函数)
  ├─► selfWriteTracker.ts (writeManagedFile)
  └─► disabledExtensions.ts (getDisabledExtensions)
```
